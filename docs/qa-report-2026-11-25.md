# KARAG — QA round on the deployed server, 2026-11-25

**Target:** http://10.10.10.25:3010 (docker compose: api, web, scheduler), seven
accounts (ceo, hr, finance, employee, admin, platform operator, engineer).

**Method:**
1. An API sweep of every endpoint, run as each role. RBAC refusals were checked
   as carefully as successes (`testbench/api_check.py`).
2. A browser walkthrough of every console page in Russian and English, light and dark.
3. Real uploads: docx, xlsx, pptx, csv, md, a scanned PDF, SQLite and Postgres/MySQL dumps.
4. Live model answers, streaming, alerts, webhooks, the rate limit and the budget.

**Result after fixes:** the sweep passes **167/167** on the redeployed server.
The backend suite passes 527 tests (7 environment-gated skips). The console
lint, type-check and production build are clean.

## What was already solid

- **RBAC:** finance never sees salaries, an employee never sees HR documents,
  and an unauthorised tool is invisible (`SkillNotFound`), not just refused.
- **Retrieval:** hybrid retrieval plus the `search_documents` tool found the
  missing pharmacy №4. Codes like `АМК-875` match exactly.
- **Files and data sources:**
  - generated xlsx/docx/pptx files open correctly;
  - the API wizard, DB wizard and per-table access work;
  - authored lookups test-run correctly (Сино, Aug 2026 = 10 381.3).
- **Guards:** a 429 with `Retry-After`, the SSRF guard, refused unsigned
  webhooks, the EN/RU switch and both themes all behave.

## Findings and status

Severity: **C** critical (data exposure), **H** high (broken feature or
security weakness), **M** medium, **L** low.

| # | Sev | Finding | Status | Fix |
|---|-----|---------|--------|-----|
| C1 | C | An admin could register `/data/karag_app.db` (every tenant's accounts and audit) as a SQLite connector and query it | **Fixed** | `SqlitePolicy`: a SQLite path must resolve inside the tenant's own upload folder or `KARAG_SQLITE_ALLOWED_DIRS`. The platform's own DB files are always denied, and symlinks, `..` and `env:` indirection are resolved first. Refusals are audited. |
| H1 | H | The sign-in screen accepted any token, and the app then looked silently empty | **Fixed** | The token is checked with `/v1/me` before it is saved, with RU/EN reasons (invalid / server unreachable / expired). Any 401 later signs out with "session expired". |
| H2 | H | Generated files were lost after a reload: history kept only the file name | **Fixed** | Files (≤25 MB) are stored with the chat. `GET /v1/chats/{id}/files/{file_id}` serves them to the chat's owner only, and deleting the chat deletes them. |
| H3 | H | The alert builder offered file makers, admin and codebase tools with English model descriptions. It had no parameter or condition inputs, and the server accepted any skill. An unknown `{placeholder}` silently dropped the custom message. | **Fixed** | Skills carry a `category`. Alerts accept data lookups only, with their arguments validated against the schema. The form has parameter fields, a condition (found anything / value crosses a limit / every time) and human names. Templates can use `{count}` and any column of the first row, and unknown placeholders stay visible. |
| H4 | H | A lookup could be offered to a wider audience than its connection or table allowed. New databases were live for "Сотрудники" while still under review. | **Fixed** | A lookup inherits the audience of the data it reads and may only narrow it. Hidden tables cannot be named. Mixed audiences need roles cleared for all of them. A new DB connection starts at the narrowest class the author is cleared for, and the wizards require an explicit audience. |
| H5 | H | No retries: one DNS failure on the server failed a whole answer | **Fixed** | `llm/retry.py`: connection, DNS and timeout errors and 408/409/429/5xx are retried with back-off, honouring `Retry-After` (OpenAI, Voyage). The Anthropic SDK retries on its own. |
| M1 | M | Configuration-token tenants and people were invisible in Admin, and the Usage gauge showed an invented 1M-token budget | **Fixed** | Configuration tenants are created on start-up. Configuration accounts are listed read-only with an "из конфигурации" badge. With no budget the gauge says "без лимита". |
| M2 | M | The classifier escalated everyday SOPs to "regulated", called payroll "financial", and preselected "Закрытые" with no evidence. Its rationale was in English. | **Fixed** | Terms were retuned: salary and payroll are HR, and "SOP" or "deviation" alone no longer escalate. Escalating needs a title hit or three distinct terms. With no evidence nothing is preselected. The rationale is built in the interface language. |
| M3 | M | Employees saw the add-document form and the delete buttons | **Fixed** | `/v1/me.can_ingest` hides both. |
| M4 | M | "Показать" (the tour) sent an English prompt, so the tour came back in English | **Fixed** | The prompt is written in the interface language (ru/tg/en). |
| M5 | M | Citation chips gave only a native tooltip, deduplicated by title, with no marker mapping | **Fixed** | Chips show their markers (`[2][5]`). Clicking one opens the quoted passages behind each marker. |
| M6 | M | The code-change (engineer) feature was offered in Docker, where there is no git checkout | **Fixed** | It is enabled only where git and a `.git` exist. The Engineering page explains why when it is unavailable. |
| M7 | M | "The answer could not be produced" appeared in English, and DB errors showed raw driver text | **Fixed** | Driver errors become one plain sentence (login refused / no such database / host not found / no answer / SSL / not a database / no table rights), with the technical text in brackets. Stored and live failures are shown in the interface language. |
| L1 | L | The assistant "try it" box showed raw Markdown | **Fixed** | Rendered with the chat's Markdown. |
| L2 | L | The audit log listed oldest first | **Fixed** | Newest first. |
| L3 | L | The DB wizard kept a stale error after switching mode | **Fixed** | The error is cleared on switch. |
| L4 | L | Field meanings in the API wizard were clipped | **Fixed** | The meaning field wraps (textarea). |
| L5 | L | The plane badge said "mixed" when documents were retrieved but not cited, or when a file was made | **Fixed** | The plane follows data lookups used and passages actually cited. |
| L6 | L | Bad base64 in attachments was accepted silently | **Fixed** | `validate=True` → 400. |
| L7 | L | Skill chips showed raw machine names | **Fixed** | Humanised. |
| L8 | L | Uploaded titles kept the file extension | **Fixed** | "Положение_об_отпусках.docx" → "Положение об отпусках". A re-upload still replaces an older "….docx" copy. |
| L9 | L | `POST /v1/me/language` answered 404 for configuration accounts | **Fixed** | 200 with `"stored": false`. The console keeps the choice locally. |
| L10 | L | The audit log described any tool run as "запросил живые данные" | **Fixed** | "воспользовался инструментом". The tool name stays beneath it. |

## Verified after redeploy

- **API sweep:** 167/167. New checks this round:
  - the platform DB is refused as a source;
  - alerts refuse a file maker and unknown lookups;
  - a saved chat file downloads after reload, and not for another user;
  - DB errors start with a plain sentence;
  - an everyday SOP is classified "operational".
- **In the browser (ceo, RU, dark):**
  - the alert form lists only the three data lookups, with a SQL field and conditions;
  - an answer that made an .xlsx and cited a document shows "знания", a readable tool chip and the passage panel;
  - after a reload, `report.xlsx` is still downloadable (fetched in-page: 200, valid xlsx);
  - the audit log is newest first.
- **Engineer account on the server:** `code_changes_available: false`.

## Not exercised in the browser this round

Each is covered by code review, type-checks and the API sweep instead:

- **Sign-in rejection:** checking it would have signed the real browser session out.
- **The wizards' "choose an audience" step:** it needs a new DB/API connection made through the UI.
- **The Documents "no evidence" notice:** it needs an upload through the file picker.

## Known limitations (not defects)

- **Classifier:** keyword suggestions still miss some labels in the eval corpus.
  The supplier contract is labelled financial but suggested operational, and the
  store directory and returns policy (public) have no evidence. Nothing is
  applied automatically, and a suggestion without evidence is not preselected.
- **Old titles:** documents uploaded before this round keep ".docx" in their
  titles until re-uploaded.
- **Authored lookup names:** these lookups have no stored human title, so the
  alert picker shows their transliterated name ("Vyruchka aptek za period").

## Re-running

```bash
KARAG_QA_URL=http://10.10.10.25:3010 KARAG_QA_TOKENS=<tokens file> KARAG_QA_SCAN=<scanned.pdf> \
  .venv/bin/python testbench/api_check.py
```

The sweep makes a handful of real model calls (cents) and deletes everything it creates.
